# VNEDGE — End-to-end code-flow & feature-goals audit (2026-08-15)

Method: four parallel auditors traced the codebase against the CLAUDE.md invariants
with file:line evidence; the three headline findings were then reproduced/verified
by hand. Repo at `97083b8`.

## Verdict
**The architecture and its core invariants are largely MET.** Confirmed solidly
enforced: gateway non-bypass (single submit path), sizing from risk/stop + rounds
down, frozen risk configs, 3-gate live + exact-phrase, leverage caps incl. the 30x
hard bound, daily-loss halt (min fixed/pct, entry-only), explainable rejections
(all failed checks), read-only dashboard (no control route), lookahead structurally
impossible, one shared sizing path, observe-only cost overlay, walk-forward OOS
discipline, human-gated promotion, lane_health + #5 orphan filter.

**The defects cluster in two places:** (1) the **live-order path** (`live_trader`),
which is dormant — no running service executes it — so these bite only on live
activation, but MUST be fixed before it; and (2) the **research→promotion path**,
where one gap (exit parity) bites *today* because it changes what promotion evidence
means.

## Findings (de-duplicated, severity-ranked)

### HIGH
**H1 — Kill switch is non-functional in the live entrypoint.** `live_trader_main.py:171`
does `KillSwitch(kill_file="KILL")` — a `str`, but the field is `Path` with no
coercion (`kill_switch.py:40`). `is_active` calls `.exists()` on a str → reproduced
`AttributeError`. It's invoked on every entry (`order_manager.py:154` → `risk_manager.py:178`),
unguarded, so the first entry crashes the live session and **`touch KILL` cannot halt
a live bot**. Fail-loud (crash, no bad order) not fail-open. One-line fix:
`KillSwitch(kill_file=Path("KILL"))` (every other construction site already passes a Path).

**H2 — Position reconciliation is presence-only** *(cross-confirmed by two independent
auditors)*. `live_trader.py:612-613`: `expected = self._plan is not None` vs
`actual = account.open_positions > 0` — only zero-vs-nonzero. A wrong-side or
wrong-size venue position (partial fill / liquidation / manual trade / shared account)
reads as "agreeing", the mismatch never trips, and `ActiveExitState` manages stop/TP
against the wrong side. This is the exact silent-divergence the "reconciliation
mismatch ⇒ fail closed" invariant exists to catch. Fix: compare symbol + signed size,
not a count.

**H3 — Unresolved/working orders are not rehydrated across a restart.** `OrderManager`
starts `self.orders = {}` every process; L2 seeded only the dedup registry, not order
state. After a crash: `has_unresolved_orders` resets to False → entries re-allowed, and
`LiveReconciler` can't resolve a pre-crash `TIMEOUT_UNKNOWN`/working order because it
iterates the empty `self.orders`. The WAL has the records but nothing replays them into
`ManagedOrder` state. (`run_pre_live_checklist_from_env` also hardcodes
`has_unresolved_orders=False`, `pre_live_checklist.py:192`.) A filled-into-position
timeout is later caught as an orphan; a still-working order is invisible.

**H4 — The shared exit engine is never enabled on the promotion/backtest path** *(bites
today)*. `use_active_exit` defaults `False` (`backtester.py:86`) and is set `True` only
in `tests/test_backtester_breakeven.py` — no walk-forward/promotion harness turns it on.
So strategies are **judged on the legacy single-stop/TP exit** while capital lanes run
`ActiveExitState` + ATR trail + TP-ladder + fee-aware breakeven (e.g. crypto_trend DOGE
`trail_atr_mult=3.0`). The OOS evidence a lane is promoted on was measured on a *different,
simpler exit* than it trades — defeating "backtest and live can't diverge." Fix: default
or force `use_active_exit` + matching trail/ladder params in the walk-forward config so
the judged exit equals the LaneSpec exit.

### MEDIUM
- **M1 — Live per-bar loop body is not exception-guarded** (`live_trader.py:522-562`).
  `om.submit` maps only `AdapterRejection`/`AdapterTimeout`; an unmapped `KeyError`/`TypeError`
  (e.g. `str(result["id"])`) or a raw-candle `float()` parse error propagates and terminates
  `run()`. Loud, not silent (exit plans persist for restart), but no bar-level containment on
  the real-money path. Wrap the bar body; treat a bar fault as skip-and-continue.
- **M2 — The real-economics fill path is built but wired into no running live path.** L1-inc3
  added `PrivateStreamEventApplier` fill→ledger, but `live_trader_main.py` constructs the
  session with no `fill_ledger` and no private stream, and `require_private_stream` defaults
  False (so `private_stream_ready()` is always True). Live would report `fills=0/fees=0` and
  enter with zero private-stream confirmation. Wire the stream + ledger into `live_trader_main`.
- **M3 — Pre-live checklist is optional at session construction** (`live_trader.py:91,113`).
  `pre_live_report` defaults None ⇒ unenforced. A direct `LiveTraderSession` with live settings
  + a paper-style RiskConfig (`daily_loss_halt_enabled=False` or `fixed_margin_usd` set) would
  run real orders with the halt off / leverage-based sizing. 3 gates + adapter confirm still
  apply, so defense-in-depth weakness not a full bypass. Fix: require a cleared report when
  `settings.is_live`.
- **M4 — Shadow runs a separate exit reimplementation.** `shadow_outcomes.py:273-382` has its
  own `resolve_bar`/`_check_exit`, resolves a single TP, and skips the TP-ladder partials +
  fee-aware breakeven — yet comments claim "byte-identical" to `ActiveExitState` (false for any
  laddered strategy). Observation-only, so no bad trade, but it misinforms promotion review.
- **M5 — Private-stream fill accounting can double-count `filled_quantity`** (latent; stream
  unwired). `apply_venue_order_update` uses `max(current, cumulative)` while
  `apply_venue_fill_update` does `+=` per trade; a cumulative order event before the per-trade
  events overshoots `intent.quantity`. Reconcile to one accounting basis before wiring M2.

### LOW / cosmetic
SYSTEM/RISK chips start "ok" so a fully-cold snapshot reads nominal (unknown-faking-ok at the
rollup only); client chip fallback keys off cumulative `decision_skips` vs the server's current
`arm_blocked` (latent, server always annotates); arm-gate bare-except is fail-OPEN (mitigated by
`_tm_degraded` pre-check); programmatic kill not durable if the KILL write itself fails; ladder
evidence engine `evaluate_live_ladder` has zero callers (progression = env attestation);
dedup registry burns keys for rejected intents (bounded by one-eval-per-bar); walk-forward PF/
payoff gates reconstruct win/loss from rounded stats instead of the raw trade list; `paper_runner`
(demo only) is a third exit variant; `phrase_ok` refusal diagnostic is misleading; `app.py`
docstring understates the route surface; token accepted via `?token=` query param.

## Recommendation (priority order)
1. **H4** — align the promotion exit with the deployed exit. Bites now; changes what every
   paper/live promotion decision means. Highest value.
2. **H1** — one-line kill-switch Path fix. Trivial, and it's the last line of defense.
3. **H2, H3, M1, M2, M3** — the live-path hardening block; all dormant, all required before
   any live activation. Do as one pass with the L-series.
4. LOW/cosmetic — batch opportunistically.
