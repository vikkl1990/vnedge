# Bounded timeframe/param sweep with Deflated-Sharpe honesty gate (2026-08-03)

Ran the "backtest all combinations across timeframes" request the ONLY honest
way: bounded grid + walk-forward OOS + a multiple-comparison penalty.

Scope: BTC, 3 mechanic families (funding-carry, funding-MR, crypto-trend) x
6-config param grids x timeframes 5m/15m/1h/4h = 72 configs; 45 had >=10 OOS
trades. Each config walk-forwarded (train/test scaled per TF). Whole set
penalised by Deflated Sharpe (ml/validation.py), n_trials=45.

## Result

- Best config: 4h funding-carry (cp0.70), 31 OOS trades, +$55, raw per-trade
  Sharpe 0.216.
- **DEFLATED SHARPE = 0.097 (FAILS; need >=0.95).** The best-of-72 backtest is
  not convincingly real once search breadth is accounted for.
- NO 5m or 15m config reached the top 8 — the edge lives at 1h/4h, not sub-15m
  (fee-dominated noise). 1m not run (structurally noisier; would be worse).
- The top configs are the families already deployed; the sweep manufactured no
  new edge that survives the penalty.

## Conclusion

An unpenalized sweep would have "found" 4h-carry as a winner (+$55, Sharpe
0.216). The DSR shows it is noise dredged from 45 trials. This is the honest
answer to "backtest all permutations": done correctly (DSR), the combinatorial
search finds NOTHING promotable. The two pre-registered earners remain the edge.
