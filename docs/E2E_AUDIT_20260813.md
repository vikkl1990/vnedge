  decision-at-close, fill-at-next-open. No lookahead.
- **Feed-continuity guard is enforced** (not just logged) — gap→REST heal or
  reduce-only; stall→reduce-only; new entries blocked, exits keep flowing.
- **Funding strictly backward** — a bar only sees funding already printed; Delta's
  unwarmed percentile is NaN-masked (no bogus extremes).
- **Single gateway choke-point** — every order path (paper, live, shadow-eval,
  emergency-flatten, scalper hot path) routes through `gateway.evaluate`. No bypass.
- **Journal-before-submit · TIMEOUT_UNKNOWN fail-closed · sizing rounds down /
  rejects too-small · observe-only overlays** — all correct.
- **Paper money-math** — fees, realized PnL, no double-count between ledger and
  tracker; **hash-chain verification** refuses a corrupt tail. Sound.
- **Dashboard read-only** — no arm/kill/order/promote route; token-gated;
  chips/bands share the arm-gate's classifier (B2/B3 holds — UI can't show green
  while the bot fail-closes).

## 🔴 Live-path completion — the prerequisite for ANY exchange going live

All three exchanges (Binance, Delta India, Bybit) promote through the same
`LiveTraderSession`, which is a scaffold:

| # | Gap | Where | Consequence |
|---|-----|-------|-------------|
| L1 | **No settlement accounting** — `_report()` hard-codes fills/fees/PnL/dd = 0; no tracker, no fill ledger, no account store | `live_trader.py:447-457` | real capital has no immutable fill record, no equity/drawdown tracking |
| L2 | **Cross-restart idempotency** — `IntentRegistry` in-memory, never rebuilt from the journal; a re-presented intent gets a fresh client_order_id | `order_manager.py:77,107` | double-book window after a restart |
| L3 | **No entry-hygiene gates** — arm-gate / protections / daily-factory are paper-only | `live_trader.py:355-363` | paper-validated behaviour not reproduced live |
| L4 | **Reconciliation can't rebuild from venue** — halt latches but `_plan`/position never resynced; an untracked venue position deadlocks until operator flatten | `live_trader.py:389-426` | no auto-recovery |
| L5 | **Submit-path read faults crash the loop** — the consecutive-read-failure guard covers only `_reconcile_positions`, not `_submit_entry/_exit` | `live_trader.py:164-217` | an account-read fault during submit kills the loop |
| L6 | **Live config invariants unenforced** — a live `RiskConfig` with `daily_loss_halt_enabled=False` passes the pre-live checklist | `pre_live_checklist` vs `risk_config` | daily-loss halt silently no-ops |
| L7 | **Mark-to-market peak inflates drawdown** — peak includes unrealized + is persisted; a transient spike raises DD forever | `portfolio_tracker.py:70` | a blip can trip the HARD dd gate (affects funding_mr's 7.35% today) |
| L8 | **Programmatic kill/halt not durable** — only `touch KILL` survives restart | `kill_switch.py:50-62` | a one-pass window with entries re-enabled after restart |

**#1 fix:** give `LiveTraderSession` the same settlement + gate + idempotency stack
the paper session already has — ideally by having live **embed the shared
components** (tracker, fill ledger, account store, ActiveExitState — A1 already
shared the exit engine), not reimplement. Until then, live is not production-ready
for any venue. This is safe today (live gates closed) but it is real work, not a
keys-and-go step.

## Sequenced remediation

**Phase 1 — running-paper bugs (fix now; they affect today's operator view):**
O1 journal P&L reconcile (sum full population or label as recent-window) · O2
reset `decision_skips` when the condition clears · O3 make alert conditions
null-safe (don't let a safety rule fail silent) · O4 fix the `quote` shadowing ·
O5 trim the forming bar from the warmup seed (or replace-on-equal-ts in
`_append_candle`).

**Phase 2 — complete the live path (prerequisite for live_small on ANY exchange):**
L1 settlement stack on `LiveTraderSession` (embed tracker + fill ledger + account
store) · L2 seed `IntentRegistry`/orders from the journal at startup · L5 guard
submit-path reads · L3 entry-hygiene gates on live · L4 reconciliation rebuild ·
L6 enforce live config invariants in the checklist · L7 realized-only peak (or a
separate unrealized peak) · L8 durable programmatic kill.

**Phase 3 — per-exchange live activation** (after Phase 2): mainnet trade-only
keys + a promoted strategy + the pre-live checklist, per venue (Delta India first).
