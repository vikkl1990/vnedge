# Pre-Registration — regime_v0

**Model id:** `regime_v0_20260812`
**Date locked:** 2026-08-12
**Family:** regime · **Algorithm:** rules (causal) · **Status on register:** research → candidate
**Role:** control layer — a **filter and sizer input**, never an alpha signal.

---

## 1. Why (economic role, not prediction)

Regime detection answers *"what kind of market is this right now?"* — trend,
chop, or stress — so thin edges are only armed where they can work and are
stood down where crowding can stay crowded or volatility is unstable. It does
**not** predict direction. It protects the platform's edges and explains flat
books on the operator cockpit. It is lane-agnostic: funding, momentum, and
future scalp/swing builders all subscribe to the same reading.

## 2. Locked taxonomy + rules (frozen — no tuning after this)

Built **only** from the existing causal primitives in `strategy/regime.py`
(`add_regime_columns`): efficiency ratio `er`, `atr_pct` (trailing ATR
percentile), and the EMA-alignment trend flags. No new features.

| State | Rule (evaluated at a closed bar) | allow_long | allow_short |
|-------|----------------------------------|:----------:|:-----------:|
| `high_vol` | `atr_pct >= 0.90` (**dominant** — overrides direction) | ✗ | ✗ |
| `trend_up` | `regime_trend_up` and not high_vol | ✓ | ✗ |
| `trend_down` | `regime_trend_down` and not high_vol | ✗ | ✓ |
| `chop` | trending is False and not high_vol | ✓ | ✓ |
| `unknown` | any regime feature is NaN (warm-up) | ✓ | ✓ (neutral pass-through) |

Frozen params: `RegimeParams()` defaults (`er_trend_min=0.30`,
`ema_fast=24`, `ema_slow=96`, `er_window=48`, `atr_window=24`,
`atr_pct_window=240`) + `high_vol_pct=0.90`.

**Confidence** (0–1, for soft sizing): `high_vol → atr_pct`;
`trend_* → er`; `chop → clip(1 − er, 0, 1)`; `unknown → 0.0`.
A strategy may consume the **hard** allow-flags OR scale size by `confidence`.

`unknown` is a **neutral pass-through**, not a block: the strategy's own
`warmup_bars` gate already prevents trading on insufficient data, so regime_v0
must not manufacture a hidden block during warm-up.

## 3. Output schema (locked)

```
label: trend_up | trend_down | chop | high_vol | unknown
allow_long: bool
allow_short: bool
confidence: float                  # 0..1
scores: {trend_up, trend_down, chop, high_vol}   # monotone rule scores, not calibrated probs
features_used: [er, atr_pct, regime_trend_up, regime_trend_down]
model_id: regime_v0_20260812
```

## 4. Non-goals (forbidden for v0)

- No direction prediction / alpha use — filter + sizer input only.
- No new features, no threshold tuning after this lock.
- Freeze regime_v0 **before** any edge sealed test that uses it, so the regime
  cannot be fit to the edge's evaluation window.
- Do not replace v0 with an HMM until an HMM beats it OOS on the same
  promotion machinery (existing CLAUDE.md rule).

## 5. Evaluation criteria (how a regime is judged — not win rate)

| Metric | Bar |
|--------|-----|
| Causal purity | features/labels use only data ≤ the decision bar (unit-tested) |
| Stability | median run-length in a state ≥ a few bars on stable data (no 1-bar flip-flop) |
| Filter value | an edge's PF **with** vs **without** the regime overlay on sealed data (reported when an edge uses it) |
| Risk value | max DD / tail with the `high_vol` stand-down overlay |

## 6. Promotion path

`research` (registered) → `candidate` (this doc) → shadow overlay on a lane →
if it improves sealed risk/edge metrics → `paper` → `promoted`. An HMM v1 must
beat this baseline OOS to displace it. Failure → `rejected`, archived note.
